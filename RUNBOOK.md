# Anomaly Engine — Stack Runbook

How to start, verify, and stop the local stack.

All commands run from the **repository root** (the folder containing
`start-dev.ps1`). Paths below are relative, so the repo works from any drive.

---

## 1. Start everything

```powershell
powershell -ExecutionPolicy Bypass -File .\start-dev.ps1 -IncludeFrontend
```

This starts eight processes, detached, and waits for the gateway to answer
before printing `Done`. Ports that are already listening are skipped, so
running it twice is safe.

Expect roughly 30–60 seconds on a cold start (the NLP engine loads FinBERT).

---

## 2. What should be running

| Port  | Service           | Health check                            |
|-------|-------------------|-----------------------------------------|
| 27017 | MongoDB (`mongod`) | `Test-NetConnection 127.0.0.1 -Port 27017` |
| 8000  | api-gateway       | http://localhost:8000/health            |
| 8001  | ingestion-us      | http://localhost:8001/health            |
| 8002  | ingestion-market  | http://localhost:8002/health            |
| 8003  | nlp-engine        | http://localhost:8003/health            |
| 8004  | backtester        | http://localhost:8004/health            |
| 8081  | mongo-api         | http://127.0.0.1:8081/health            |
| 3000  | frontend          | http://localhost:3000                   |

One-liner to check all of them:

```powershell
foreach ($p in 27017,8000,8001,8002,8003,8004,8081,3000) {
  $c = Get-NetTCPConnection -LocalPort $p -State Listen -ErrorAction SilentlyContinue
  "{0,5}  {1}" -f $p, ($(if ($c) { 'UP  PID ' + $c.OwningProcess } else { 'DOWN' }))
}
```

Everything should read `UP`. If a port shows `UP` but the page is broken, it is
probably an orphan from a killed shell — see section 5.

Useful URLs once running:

- Dashboard: http://localhost:3000
- API docs (Swagger): http://localhost:8000/docs
- Gateway health: http://localhost:8000/health

## 3. Manual start (only if the script fails)

Start in this order; later services call earlier ones.

```powershell
# 1. MongoDB
New-Item -ItemType Directory -Force -Path .\services\mongo-api\data\db   | Out-Null
New-Item -ItemType Directory -Force -Path .\services\mongo-api\data\logs | Out-Null
.\scripts\run-mongod.cmd

# 2. Express API on :8081
cd .\services\mongo-api
npm install          # first time only
cd ..\..

# 3. Python services on :8001-:8004 and :8000
.\scripts\run-ingestion-us.cmd
.\scripts\run-ingestion-market.cmd
.\scripts\run-nlp-engine.cmd
.\scripts\run-backtester.cmd
.\scripts\run-api-gateway.cmd

# 4. Frontend on :3000
cd .\services\frontend
npm install          # first time only
npm run dev
```

The `scripts\run-*.cmd` launchers are generated by `start-dev.ps1` and are
gitignored, because they contain environment values from your local `.env`.
Run `start-dev.ps1` once to create them.

Each Python service must be started with its own service folder as the working
directory, because they import `app.*` relatively.

---

## 4. First-time setup

```powershell
Copy-Item .env.example .env
# then edit .env and fill in the values
```

The stack starts without all of them, but Supabase mirroring, Redis, and
Finnhub features stay disabled until they are set. `.\scripts\verify-env.ps1`
checks which are present.

---

## 5. Stop / restart

```powershell
# find and kill the stack
Get-Process mongod,node,python -ErrorAction SilentlyContinue | Stop-Process -Force
```

Then re-run section 1. To kill a single orphan, take its PID from the section 2
table and run `Stop-Process -Id <pid> -Force`.

---

## 6. Common failures

| Symptom | Cause | Fix |
|---|---|---|
| `address already in use` | Orphan process still holding the port | Section 5, then restart |
| Frontend shows `—` everywhere | Gateway not up yet, or pipeline never ran | Check :8000/health, then see `docs/PYSPARK_RDD_PIPELINE.md` |
| `ModuleNotFoundError: app` | Python service started from the wrong folder | `cd` into `services\<name>` first |
| Mongo connection refused | `mongod` not running | Section 3, step 1 |
| NLP engine slow on boot | FinBERT weights loading (uncached) | Wait ~60s; first run also downloads ~400 MB |

---

## 7. What not to press during a demo

- **"Update from SEC"** — live network calls, slow, can fail on stage.
- **"Run the analysis"** — a full PySpark run takes about 10 minutes. The
  previous results stay visible while it runs, but do not start it just before
  presenting.

The curated results in `data/curated/latest/` are the ones the dashboard reads.
See `docs/PYSPARK_RDD_PIPELINE.md` for the numbers and the explanation of each pipeline stage.
